## Рабочий конвейер

```text
DICOM / ZIP / MHA / NIfTI
  → импорт, серии и физическая геометрия
  → TotalSpineSeg отдельным процессом
  → проверка маски на исходной сетке
  → предполагаемые уровни и ROI дисков
  → геометрия, координаты и артефакты
  → JSON с отдельными состояниями анатомии и диагностики
```

| Компонент | Реализованная ответственность |
|---|---|
| `uploads.py` | Приём файлов и безопасная обработка ZIP |
| `imaging.py` | Импорт DICOM/MHA/NIfTI, проверка геометрии, метаданные серий |
| `segmentation.py` | Подготовка входа и запуск TotalSpineSeg, проверка версии/весов и выходной маски |
| `levels.py` | Пять предполагаемых уровней, физические ROI и измерения по маскам |
| `lumbar.py` | Результат анализа серии с отдельными статусами локализации, нумерации и диагностики |
| `repository.py` | SQLite: исследования, задания, результаты и ссылки на артефакты |
| `main.py` | HTTP API, локальная последовательная очередь и выдача артефактов |

TotalSpineSeg использует готовую nnU-Net и работает в отдельном `.venv-tss`.
API не импортирует PyTorch. Пакет зафиксирован на `20260730`, веса — на
`r20260730`; скачивание выполняется заранее через `scripts/fetch_totalspineseg.py`.
Запуск API не инициирует загрузку весов. Готовность провайдера видна в `/capabilities`.

Выход TotalSpineSeg содержит анатомические классы. По дисковым классам создаются
предполагаемые L1–L2…L5–S1, сохранённые на исходной физической сетке. Нумерация
получает `needs_confirmation`: переходная анатомия не разрешается одной меткой
модели. Маска канала не является отдельной маской дурального мешка; класс
спинного мозга не устанавливает патологию конуса.

Для найденной ROI сохраняются изображение, метки и бинарная маска диска,
границы и координаты. Геометрические измерения содержат метод, единицы и
источник. Площадь канала оценивается только при подходящем разрешении;
косая сетка требует проверенного переформатирования. Эти измерения имеют
статус `research_only` и пока не переводятся в клинические степени стеноза.

## Диагностические состояния

Рабочий API запускает один конвейер — `lumbar_levels`. Грыжа, bulging,
снижение высоты, морфология, сторона, размеры грыжи, миграция, степени стеноза,
корешковый конфликт, мешок и конус пока получают `not_assessed`.

`completed` означает завершённую обработку задания. Отсутствие маски,
неподключённая диагностическая модель или ошибка сегментации не создают
заключение «норма». Каждый уровень содержит собственное состояние локализации;
каждое диагностическое поле — состояние оценки и причину отказа.

Артефакты выдаются через `/analyses/{id}/artifacts/{artifact_id}`.
Публичный JSON содержит ссылки и контрольные суммы файлов, а не внутренние
пути сервера. Параметры обработки и происхождение маски сохраняются с результатом.

## Подготовка дисковых данных

`scripts/prepare_disc_dataset.py` создаёт ROI из опубликованных масок SPIDER
либо предсказаний TotalSpineSeg. Из 64 загруженных T2 исследований подготовлены
447 reference ROI; `artifacts/spider-disc-reference-audit.json` (аудит: исторический артефакт исходного проекта; в этом checkout не хранится)
показывает покрытие, распределения меток и разделение пациентов.

SPIDER использует относительную нумерацию дисков снизу, а не подтверждённые
анатомические имена. Эталонные маски соединяются с CSV через
`mask_label = 200 + IVD label`; предположение `201 = L5–S1` не используется.
Для ROI из TotalSpineSeg требуется подтверждённое сопоставление конкретной
серии, иначе метки патологии остаются неизвестными.

Зафиксированное разделение пациентов находится в
`artifacts/spider-patient-splits.json`. Все серии и диски пациента остаются
в одной группе. Подготовленные ROI содержат опубликованные целевые метки;
обученных диагностических предсказаний в них нет. Следующий этап — три
детектора внутри ROI и их проверка на уровне дисков и пациентов по плану MVP.
